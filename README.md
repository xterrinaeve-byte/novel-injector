# Novel Injector（小说注入器）

SillyTavern（酒馆）第三方扩展。先把小说清洗成压缩正文、剧情节点和角色资料，再在聊天时注入相关内容；支持向量检索、穿书进度、用户代入、世界设定与文风。

> **已经支持自定义上下文注入位置。** 打开插件 → **处理** → 向下找到并展开 **注入设置** → 展开要调整的分类，即可设置 **注入位置、注入深度、消息角色**。各类内容可以分别设置，详见下文。

[安装与上手](#安装与上手) · [注入说明](#注入位置与内容) · [穿书与代入](#穿书与用户代入) · [常见问题](#常见问题) · [更新记录](./更新记录.md)

## 安装与上手

在酒馆的扩展安装入口粘贴：

```text
https://github.com/ZZZa-o/novel-injector
```

安装后刷新页面，点击顶部的书本图标打开插件。手动安装则把仓库放到 `SillyTavern/public/scripts/extensions/third-party/novel-injector`，目录内须包含 `manifest.json`、`index.js`、`lib/` 等文件。

1. **处理** → 上传 `.txt` 或 `.mobi` 小说。
2. 点清洗区域的设置齿轮，填写 **清洗 API 地址、Key、模型**。需要兼容 OpenAI Chat Completions 的接口；插件不提供模型。
3. 点 **开始全自动清洗**，等待处理。清洗会产生压缩正文、剧情节点和角色资料，支持暂停与续跑。
4. **阶段** → 开启想让 AI 参考的阶段，再回到聊天窗口发消息。需要调整阶段划分时，到 **剧情** 页操作。

**不做向量化也能使用。** 想按语义检索片段，再到处理页配置兼容 OpenAI Embeddings 的向量接口，选择阶段并向量化。聊天模型与向量模型用途不同，不能混填。

| 页面 | 常用操作 |
|---|---|
| 处理 | 上传、清洗、API 配置、文风生成、向量化、注入设置 |
| 剧情 | 剧情节点编辑、阶段划分、世界设定、偏差分析、穿书模式 |
| 角色 | 角色资料、注入开关、AI 更新人设、用户代入 |
| 阶段 | 阶段开关、标题与概括、角色演绎提示词、未向量注入方式 |
| 设置 | 插件总开关、全局提示词、自动保存、主题、小说库、导入导出 |

## 注入位置与内容

**入口：处理 → 注入设置。** 先展开“注入设置”，再展开其中的“角色人设”“阶段剧情（未向量）”“向量块”等分类。

- **注入位置**：`主提示前`、`主提示后`、`聊天内` 三选一。
- **注入深度**：选择“聊天内”时，`0` 表示对话末尾；数字越大，插入位置越靠前。它不是阶段编号，也不是召回数量。
- **消息角色**：`系统`、`用户`、`助手` 三选一，决定这段资料以哪种消息身份发给模型。

| 分类 | 发给 AI 的内容 | 默认位置 / 深度 |
|---|---|---|
| 全局提示词 | 内置头部、尾部规则 | 头部：主提示前 / 0；尾部：聊天内 / 0 |
| 角色人设 | 已开启的角色资料 | 主提示前 / 4 |
| 阶段剧情（未向量） | 剧情节点或压缩原文 | 聊天内 / 4 |
| 偏差注入 | 已分析出的剧情偏差与分支事实 | 主提示前 / 0 |
| 向量块 | 根据对话检索到的相关片段 | 聊天内 / 4 |
| 世界设定 | 已开启且有内容的世界设定分类 | 主提示前 / 4 |
| 文风 | 已生成的文风执行指南 | 主提示前 / 4 |

以上默认消息角色均为“系统”。全局提示词的来源在 **设置** 页选择：不使用、跟随酒馆预设、使用插件内置。跟随酒馆预设时，可指定插件使用的已保存预设，不影响前台 RP 的预设选择。位置设置只决定资料放在哪里，**不会自动生成资料或打开对应模块**。

### 阶段与向量有什么区别？

**阶段就是一组剧情的开关单位**，例如一卷或一个篇章。普通模式下：

| 阶段状态 | 如何注入 |
|---|---|
| 已开启、已向量化 | 根据当前对话检索相关片段 |
| 已开启、未向量化 | 直接注入该阶段的剧情节点或压缩原文 |
| 已关闭 | 不参与普通模式的阶段注入 |

直接注入的内容在 **阶段 → 未向量注入** 中选择：“剧情节点”更省 Token，“压缩原文”细节更多。

普通模式的直接注入默认上限为 **32000 Token**，可在 **处理 → 注入设置 → 阶段剧情（未向量）** 调整。超出时优先保留当前阶段，再尝试阶段概括，仍放不下的阶段会省略。页面会显示本轮估算用量与省略情况。

**角色、世界设定、文风等有各自的开关或内容条件，不由阶段开关统一控制。** 想停用全部注入，到设置页关闭插件总开关。

## 清洗与常用参数

清洗统一使用 **设置 → 全局提示词** 中的来源，不再单独选择清洗模式：

| 全局提示词来源 | 清洗请求组成 |
|---|---|
| 内置提示词 | 头部、尾部作为独立消息，按全局位置、深度和角色加入请求；清洗规则、前段参考、本段原文与执行指令分别保留 |
| 跟随酒馆预设 | 读取选定预设的已保存提示词，保留启用条目的角色、顺序和深度，把本次资料与执行指令放入 `chatHistory` 槽位 |
| 不使用 | 只发送清洗规则、资料边界、前段参考、本段原文与执行指令 |

清洗始终使用清洗面板配置的 API 和模型。“插件使用的预设”可选择具体名称，也可保留“跟随前台当前预设”。指定名称后，插件读取该预设的已保存提示词，前台可以使用另一个预设 RP；所选预设被删除时会提示重新选择。新增或更名后，可点击刷新按钮更新列表。

默认位置下，内置全局头部与清洗规则分别作为两条 `system` 消息发送，随后是小说资料和执行指令两条 `user` 消息；预览与实际请求使用同一份消息结构。

预设中的临时历史只用于本次清洗，不写入实际聊天，也不带入前台角色卡、世界书和聊天记录。小说原文不会经过宏展开或身份措辞替换；未启用 `chatHistory` 时，资料追加到预设末尾，预览中会说明。升级保留全局来源和已保存的自定义清洗提示词，移除旧版单独的清洗模式设置。

- **请求结构预览和失败响应记录 / 查看请求**：预览指定分段的消息角色、顺序、全局来源、预设名称和正文。预览不会调用模型；实际发送的请求及失败响应另有记录，仅在当前页面会话保留最近 10 次请求，响应最多展示 24000 字符，不展示接口凭据。
- **续跑清洗**：保留已完成分段，补齐失败和未完成的分段。
- **重新清洗**：先弹出确认框；确认后清空当前清洗结果、剧情、角色、阶段划分和向量索引，从头处理。只是补失败段时，请用“续跑清洗”。
- **生成此段**：只处理选中的一个分段。
- **自动续跑清洗**：默认关闭。开启后会反复补齐未完成分段，直到全部完成；每轮等待 3～30 秒，随时可暂停，全部完成后弹窗提醒。
- 自动清洗中，每段每轮**最多尝试 3 次**。失败提示会显示段号、具体原因和是否还会重试；主动暂停、跳过不会冒充接口故障。
- 同一段的重试复用首次组装的消息与模型配置。单段和自动清洗都优先使用紧邻前段已完成概括的末尾 800 字符作为参考；前段未完成时使用其原文末尾。

| 参数 | 默认值 / 说明 |
|---|---|
| 每段大小 | 100 KB；大段反复超时或截断时可调小，已完成分段会保留 |
| 清洗请求超时 | 15 分钟 |
| 清洗限速 / 并发 | 3 次/分钟 / 1 |
| 向量限速 / 并发 / 每批数量 | 3 次/分钟 / 1 / 16 |
| 基础向量召回 | 参考最近 3 条消息，相似度阈值 0.5，最多召回 3 段；还可补充原著前情 |
| 自动保存 | 默认关闭，需要在设置页手动开启 |

## 穿书与用户代入

在 **剧情** 页开启穿书模式，用正文状态栏或弹窗管理进度。

- 按归档进度确定当前节点，完成节点后继续推进；翻看预览不会改变实际注入节点。整阶段完成后不会自动跨阶段，需要手动切换。
- 穿书模式的直接注入只发送**当前节点**；选择“压缩原文”时发送该节点所在的一个清洗分段。当前节点或正文不可用时会回退到阶段资料。
- 暂停会停用剧情直接注入及开场、推进、持续提示词；向量召回仍可运行，沉浸模式由自己的开关控制。
- 沉浸模式约束角色的信息边界；轻量化召回会裁掉明显晚于当前节点的内容，减少剧透。也可让 AI 推演后文建议。
- **穿书模式会从更早阶段召回前情，包括已关闭的历史阶段。** 关闭历史阶段不等于禁止它作为前情出现。
- 穿书进度按聊天独立保存。

在 **角色 → 用户代入** 中选择原著角色：

| 方式 | 效果 |
|---|---|
| 替换原角人生 | 原角色不再作为独立 NPC 注入，相关称呼按用户身份替换 |
| 扮演原角本人 | 将原角色资料作为用户的既有身份与人物基础 |

代入配置按聊天保存，称呼可以手动增删。替换发生在注入层，不改小说源数据与向量索引。

原著提供参考；如果聊天已改变人物命运或关系，可在剧情页做 **偏差分析**，把已发生的分支事实提供给 AI。偏差分析默认手动触发，也可开启按楼层自动更新。

## 保存与备份

**设置 → 小说库** 可保存、加载、更新和重命名小说快照。长时间处理或编辑前，建议开启自动保存。

| 数据 | 存在哪里 |
|---|---|
| 设置、API 配置、小说库索引 | 酒馆设置 |
| 剧情角色、压缩正文、阶段数据 | 酒馆服务端文件，分别保存为 `*_core.json`、`*_chunks.json`、`*_stages.json` |
| 向量索引 | 当前浏览器的 IndexedDB |
| 穿书进度、用户代入配置 | 当前聊天的数据 |

**跨设备或换浏览器请用“导出 ZIP”备份。** ZIP 包含小说资料、阶段与向量，不包含 API 地址、Key 和模型名。仅复制酒馆设置，不能带走浏览器里的向量。

导入支持 ZIP 和旧版 JSON。导入会新增一本小说快照，**不会立即覆盖当前工作区**；手动加载新快照后才切换。旧版 JSON 不含向量。

## 常见问题

**能不能增加“上下文注入位置”功能？**

已经有。**处理 → 注入设置 → 展开对应分类 → 注入位置 / 注入深度 / 消息角色。** 角色、阶段剧情、向量、世界设定等可以分开调。找不到时，先向下滚动并展开折叠项。

**清洗完了，为什么 AI 还是不知道小说内容？**

先检查插件总开关、阶段开关，以及对应的角色或世界设定是否开启。清洗只是生成资料，聊天时才注入；生成文风、世界设定等也需要操作各自模块。必要时查看酒馆实际发送的提示词，确认资料是否进入上下文。

**不做向量化能用吗？会不会一次把整本书塞进去？**

能用。普通模式只直接注入已开启的未向量阶段，并受 Token 上限约束；穿书模式通常只注入当前节点。想减少消耗，选“剧情节点”并只开启需要的阶段。

**清洗失败，该改哪里？**

| 提示 | 处理方法 |
|---|---|
| 429 / 请求过多 | 降低并发与每分钟请求数，稍后续跑；若提示额度不足，检查余额和配额 |
| 524 / 504 | 网关等待上游超时，稍后重试或减小分段；只提高插件超时通常无效 |
| 401 / 403 / 404 | 分别检查 Key、访问权限、接口地址与模型名 |
| JSON 语法或结构不合规、缺少 ni_meta | 模型没有按要求返回完整结果；重试，反复失败再检查清洗提示词或减小分段 |
| 输出被截断 / 缺少压缩正文 | 减小分段，检查模型输出上限与清洗提示词 |
| 请求超时 / 网络连接失败 | 检查接口、网络与酒馆服务；按需要调整超时或分段大小 |
| 模型拒绝 / 内容过滤 | 在“请求结构预览和失败响应记录”中查看实际返回；核对全局提示词及所选预设是否包含角色扮演、续写等与清洗冲突的要求 |

提示包含实际收到的接口信息。酒馆未提供原始状态码时会明确说明，不会把所有失败都归为同一种原因。只补失败段用 **续跑清洗**，无需整本重洗。

**改了阶段划分，要重新向量化吗？**

受影响阶段的索引会重置，需要重新向量化。更换向量模型后也应重建索引，避免新旧向量不兼容。向量失败可检查地址、Key、模型、限速及批量大小，并使用“诊断”查看缓存。

**AI 更新人设失败，或者某个角色被跳过？**

失败会显示原因，最多额外重试 3 次；截断时可换输出上限更高的模型。如果近期对话没有明确出现该角色姓名或可靠别名，会直接跳过，避免把别人的经历写进此人资料。

**代入角色没有可选称呼？代入会影响向量召回吗？**

称呼来自清洗提取的别名，旧数据可能没有，可手动添加或重洗相关段落。代入不会改向量索引，不影响检索。

**导入会覆盖当前小说吗？分享 ZIP 会带上 Key 吗？**

导入只新增快照，手动加载才切换。导出的 ZIP 不包含 API 地址、Key 和模型名。

**换浏览器后向量没了？**

向量存在浏览器本地。换浏览器或清空站点数据后，需要导入含向量的 ZIP，或重新向量化。

**MOBI 无法上传？**

支持无压缩与 PalmDoc 压缩的 MOBI。DRM 加密、Huff/CDIC 压缩及其他不支持的格式，请先转换为 TXT。

**顶部图标或穿书状态栏不见了？**

顶部图标在酒馆扩展菜单中开启，更新插件后先刷新页面。状态栏则检查剧情页的穿书开关与显示方式；显示异常可先折叠再展开，必要时刷新。

更多改动见 [更新记录](./更新记录.md)。排查日志可在浏览器控制台筛选 `[NI]` 或 `[NI-TB]`；提交问题时请附具体报错文字和操作步骤。
